# `src-tauri/` — Rust backend and native packaging

The Tauri 2 backend for Handy/Voize: Rust application source, Tauri
configuration, bundled native resources, and per-platform packaging inputs.

For the full architecture — the dictation pipeline, audio/VAD contracts, model
system and streaming STT — see [`context/references/codebase-v1.md`](../context/references/codebase-v1.md).

---

## Layout

| Path | Purpose |
| --- | --- |
| [`src/`](src/README.md) | **All Rust source.** Start with its README |
| `Cargo.toml` | Crate `handy`, lib name `handy_app_lib` (suffix required on Windows) |
| `Cargo.lock` | Committed. Do not regenerate casually — see below |
| `build.rs` | Tauri build script; bakes the `$ORIGIN`-relative rpath for `transcribe-libs` |
| `tauri.conf.json` | Product name, identifier, window/bundle config, updater endpoint |
| `tauri.windows.conf.json` | Windows-only bundle overlay: maps `resources/` and `transcribe-libs/` next to the exe |
| `rustfmt.toml` | Rust formatting config |
| [`resources/`](resources/README.md) | Files bundled into the app (icons, sounds, default settings, VAD model) |
| [`capabilities/`](capabilities/README.md) | Tauri permission grants per window |
| [`transcribe-libs/`](transcribe-libs/README.md) | **Gitignored.** Staged native runtime libraries, generated by the build |
| [`swift/`](swift/README.md) | Apple Intelligence bridge, macOS aarch64 only |
| [`nsis/`](nsis/README.md) | Custom Windows (NSIS) installer template |
| `gen/` | **Generated** Tauri ACL schemas — not edited |
| `icons/` | App icons for all platforms, including `android/` and `ios/` |
| `target/` | Cargo build output — never commit |
| `Entitlements.plist`, `Info.plist` | macOS bundle entitlements and plist |

## Building

```bash
bun run tauri dev                  # development, full native app
bun run tauri build                # production bundles
bun run tauri build --no-bundle    # local release binary, skips installer signing
```

`--no-bundle` is useful locally because bundled Windows release signing expects a
CI-only tool. On macOS, a cmake error can be worked around with
`CMAKE_POLICY_VERSION_MINIMUM=3.5 bun run tauri dev`.

Rust-side quality gates:

```bash
cargo test   --manifest-path src-tauri/Cargo.toml    # ~225 unit tests
cargo clippy --manifest-path src-tauri/Cargo.toml
cargo fmt
```

The Rust tests are mostly unit tests of pure logic — notably the transcription
coordinator's state machine (including deliberate toggle-parity and race
regression tests), VAD frame/timing contracts, portable-mode detection, the model
downloader, and `llm_client` request shaping. They do **not** exercise the
microphone or any native audio path.

## Cargo specifics worth knowing

- **`Cargo.lock` is committed** and must be preserved. The workspace depends on
  several git dependencies, so an unnecessary lockfile refresh is a real risk.
- `transcribe-cpp` is configured **per target**: Windows x86_64 and Linux get
  `dynamic-backends` + `vulkan`; Windows ARM is static CPU-only (Adreno Vulkan
  drivers are immature and ggml's Vulkan shader generator does not build under the
  clang-cl/lld toolchain its ARM CPU backend requires); macOS gets `metal`.
- **`[patch.crates-io]` pins a fork of `tao`** (and `tao-macros` at the same rev).
  Two separate upstream bugs are fixed there — dead titlebar buttons after
  `visible(false)` → `show()`, and a vetoed Windows shutdown. `tao-macros` must be
  patched to the *same* rev even though nothing depends on it directly, because
  Nix's `importCargoLock` otherwise hits a symlink collision. Do not "clean up"
  this patch without reading the comment block in `Cargo.toml`.
- ONNX Runtime on Windows is deliberately **CPU-only**. The DirectML EP pulled in
  a prebuilt runtime with an `/arch:AVX2` baseline that crashed at process startup
  on pre-Haswell CPUs.
- Many dependencies are forks (`rdev`, `vad-rs`, `rodio`, `hf-hub`) — check
  whether a bug lives upstream or in the fork before reporting it.

## Identity and packaging — read before distributing

The bundle still uses **upstream Handy's identity**. Audit all of these before
shipping a Voize build:

- `productName: "Handy"` and `identifier: "com.pais.handy"` in `tauri.conf.json`.
- The updater endpoint points at `github.com/cjpais/Handy/releases` with
  upstream's signing pubkey.
- The Windows `signCommand` targets upstream's Azure Trusted Signing account.
- Linux `.deb`/`.rpm`/AppImage install into `/usr/lib/Handy`.

`identifier` matters beyond branding: the single-instance plugin keys off it, so
running a dev build beside an installed Handy requires a distinct identifier *and*
distinct shortcuts (otherwise both apps respond to the same hotkey). The
`autostart` plugin keys off `productName`.

For an isolated side-by-side build, override `productName`, `identifier`,
shortcuts and updater endpoints in a local config, and use
[portable mode](../context/references/environment.md) with a `portable` marker
file next to the executable so the dev build gets its own `Data/` directory.

## Traps

- **`src/bindings.ts` is generated only in debug builds** (`lib.rs`, under
  `#[cfg(debug_assertions)]`), so after adding or renaming a command you must run
  `bun run tauri dev` for the frontend to see it.
- `tauri.conf.json` declares `"windows": []` — **both windows are created in Rust
  at runtime**. Adding a window means editing `lib.rs` (and `overlay.rs` for the
  overlay), not the config.
- `gen/schemas/*.json` and `capabilities/*.json` reference each other; changing a
  permission means editing the capability file and letting Tauri regenerate the
  schemas.
- `resources/models/` is **not** fully committed — `silero_vad_v4.onnx` must be
  downloaded (see [`resources/README.md`](resources/README.md)). A missing VAD
  model breaks recording.
- `transcribe-libs/` is **gitignored and generated** — a fresh clone will not have
  it, and an empty directory is normal. The libraries are staged by `build.rs`
  during the build. Do not look for them in version control or treat their absence
  as a bug.
