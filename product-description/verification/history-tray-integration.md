# Verification: history, tray, and integration

How to run this file: start from a clean state with onboarding completed and Parakeet Unified EN 0.6B downloaded and active, every setting at its default (History Limit 5, Auto-Delete Recordings "Keep latest 5", push to talk on), then dictate three short phrases so a few history entries exist before the first item. Keep the settings window visible unless an item says otherwise; TextEdit with a new plain-text document is the paste target. Device column values are defined in [README.md](README.md); this file uses only **mac**, **mic**, **shell**, **network-off**, and **llm** (a provider with a valid key and the "Improve Transcriptions" prompt selected). Conditions that the README names as separate devices (debug mode, Secure Input, a deleted model) are written into the Setup cell instead. For **shell** items `H` stands for `/Applications/Handy.app/Contents/MacOS/Handy`; set `H=/Applications/Handy.app/Contents/MacOS/Handy` once in the terminal. The headless items need a WAV fixture in the right format, made once with `say -o memo.aiff "testing one two three" && afconvert -f WAVE -d LEI16@16000 -c 1 memo.aiff memo.wav && afconvert -f WAVE -d LEI16@44100 -c 2 memo.aiff bad.wav`. A script can run CLI-01, CLI-02, CLI-03, CLI-10, CLI-11, CLI-12, CLI-13, CLI-14, CLI-15, CLI-16, and CLI-20 end to end (their steps are commands and their expected results are stdout, stderr, and the exit code); CLI-04 to CLI-09, CLI-17 to CLI-19, and CLI-21 to CLI-23 need a person watching the screen or speaking. The Updates items that install a build (UPD-08 to UPD-12, UPD-19, UPD-21) need a release newer than the running one; the setup for those is to install the previous release (0.9.5 from GitHub Releases) into `/Applications` first, accepting that the pre-install half of the run is on a different build than the documents describe. Say so in the Result note.
