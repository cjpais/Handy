# Секреты для обновлений: пошаговая инструкция

Нужно один раз. После этого каждая правка, попавшая в `main`, сама собирается и появляется в приложении кнопкой «Обновить». Ключи не попадают в репозиторий: они лежат только на вашем Mac и в секретах GitHub.

Сессия Claude не смогла выставить секреты сама (GitHub API секретов закрыт для неё прокси, см. [BLOCKERS.md](BLOCKERS.md), B-04). Поэтому шаги ниже делаете вы. Каждая команда копируется целиком в «Терминал».

Пока секретов нет, ничего не ломается: релизный workflow `voxa-release` проходит зелёным, собирает приложение (архив `Voxa-macos-arm64` на странице запуска), но релиз не публикует, а приложение в «О программе» покажет, что обновления ещё не настроены.

## Что понадобится

- Mac, на котором стоит Node.js (для `npx`) или Bun (для `bunx`). У вас есть Bun, команды с `bunx` ниже подойдут.
- Доступ к настройкам репозитория `Dudu2I3/voxa` на github.com.

## Шаг 1. Ключ подписи обновлений

Приложение принимает обновление, только если оно подписано вашим ключом. Ключ состоит из двух частей: секретной (подписывает) и публичной (проверяет, она зашита в приложение).

1. Создайте папку и ключ. Команда спросит пароль: придумайте и запомните его (пустой нельзя, GitHub не хранит пустые секреты).

   ```bash
   mkdir -p ~/.voxa && npx @tauri-apps/cli signer generate -w ~/.voxa/updater.key
   ```

   То же через Bun: `mkdir -p ~/.voxa && bunx @tauri-apps/cli signer generate -w ~/.voxa/updater.key`

   Появятся два файла: `~/.voxa/updater.key` (секретный) и `~/.voxa/updater.key.pub` (публичный).

2. Скопируйте секретный ключ в буфер обмена и вставьте в GitHub (шаг 3) как секрет `TAURI_SIGNING_PRIVATE_KEY`:

   ```bash
   cat ~/.voxa/updater.key | pbcopy
   ```

3. Пароль из пункта 1 вставьте как секрет `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

4. Скопируйте публичный ключ и вставьте как секрет `TAURI_UPDATER_PUBKEY`:

   ```bash
   cat ~/.voxa/updater.key.pub | pbcopy
   ```

   Вместо секрета публичный ключ можно вписать прямо в `src-tauri/tauri.conf.json`, в `plugins.updater.pubkey` (там сейчас стоит `PLACEHOLDER_SET_BY_RELEASE_WORKFLOW`). Достаточно одного из двух способов.

Сохраните папку `~/.voxa` (например, в менеджере паролей). Если потерять секретный ключ или пароль, уже установленное приложение перестанет принимать обновления: придётся скачать новую версию руками последний раз.

## Шаг 2. Сертификат подписи кода

Без него каждая сборка выглядит для macOS новым приложением, и разрешения «Микрофон», «Универсальный доступ», «Мониторинг ввода» сбрасываются после каждого обновления. Нужен один самоподписанный сертификат, который не меняется между сборками. Платный аккаунт Apple Developer не нужен, нотаризация не делается.

**Способ А. Одной командой** (в папке репозитория на вашем Mac):

```bash
bash scripts/voxa/make-signing-cert.sh
```

Скрипт создаст `~/.voxa/voxa-signing.p12`, скопирует в буфер обмена base64 файла и напечатает пароль. Значения идут в секреты `MACOS_CERT_P12_BASE64` (из буфера) и `MACOS_CERT_PASSWORD` (напечатанный пароль).

**Способ Б. Через «Связку ключей»** (без терминала, кроме последнего шага):

1. Откройте «Связку ключей» → меню «Связка ключей» → «Ассистент сертификации» → «Создать сертификат…».
2. Имя: `Voxa Code Signing`. Тип идентификатора: «Самоподписанный корневой». Тип сертификата: «Подпись кода». Нажмите «Создать».
3. В «Связке ключей» откройте «Вход» → «Мои сертификаты», выделите `Voxa Code Signing`, правая кнопка → «Экспортировать…», формат `.p12`, сохраните как `~/Desktop/voxa.p12`, задайте пароль.
4. Переведите файл в base64 и скопируйте в буфер:

   ```bash
   base64 -i ~/Desktop/voxa.p12 | pbcopy
   ```

   Вставьте как секрет `MACOS_CERT_P12_BASE64`. Пароль из пункта 3 вставьте как `MACOS_CERT_PASSWORD`. Файл `voxa.p12` потом уберите с рабочего стола в `~/.voxa`.

Имя сертификата по умолчанию подбирается само; секрет `MACOS_CERT_NAME` нужен, только если в `.p12` несколько сертификатов.

## Шаг 3. Куда вставить секреты

1. Откройте https://github.com/Dudu2I3/voxa/settings/secrets/actions
2. Нажмите **New repository secret**.
3. Имя вписывайте точно как в таблице, значение вставляйте из буфера (⌘V) или вводите.

| Имя секрета                          | Что вставить                         | Откуда                                |
| ------------------------------------ | ------------------------------------ | ------------------------------------- |
| `TAURI_SIGNING_PRIVATE_KEY`          | содержимое `~/.voxa/updater.key`     | шаг 1, пункт 2                        |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | пароль от ключа                      | шаг 1, пункт 3                        |
| `TAURI_UPDATER_PUBKEY`               | содержимое `~/.voxa/updater.key.pub` | шаг 1, пункт 4 (или вписать в конфиг) |
| `MACOS_CERT_P12_BASE64`              | base64 файла `.p12`                  | шаг 2                                 |
| `MACOS_CERT_PASSWORD`                | пароль от `.p12`                     | шаг 2                                 |
| `MACOS_CERT_NAME` (необязательно)    | `Voxa Code Signing`                  | шаг 2                                 |

Если на Mac установлен `gh` и вы вошли (`gh auth login`), то же самое делается командами. Пример для одного секрета, остальные по аналогии:

```bash
gh secret set TAURI_SIGNING_PRIVATE_KEY -R Dudu2I3/voxa < ~/.voxa/updater.key
```

## Шаг 4. Запустить релиз

Релиз запускается сам при каждом слиянии в `main`. Первый раз запустите вручную:

1. Откройте https://github.com/Dudu2I3/voxa/actions/workflows/voxa-release.yml
2. **Run workflow** → ветка `main` → **Run workflow**. (Файл workflow должен быть в `main`, то есть сначала нужно слить PR с этой итерацией.)
3. Через 15–20 минут на https://github.com/Dudu2I3/voxa/releases появится релиз `v0.10.N` с файлами `Voxa.app.tar.gz`, `Voxa.app.tar.gz.sig`, `latest.json` и `Voxa-macos-arm64.zip`.
4. Проверка ленты обновлений: откройте https://github.com/Dudu2I3/voxa/releases/latest/download/latest.json, там должны быть `version`, `notes` и `platforms`.

Если запуск остановился с красной ошибкой, её текст в логе называет причину (нет публичного ключа, сертификат без закрытого ключа, подпись не стабильна). Сообщения написаны так, чтобы их можно было выполнить.
