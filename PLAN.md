# Voxa — личная диктовка для macOS (форк Handy)

> Рабочее название **Voxa**. Меняется в одном месте: `app.config.ts` / `tauri.conf.json` (`productName`, `identifier`).

## 0. Режим работы (прочитай первым)

Ты работаешь **автономно в облачной сессии** Claude Code. Владелец не отвечает на вопросы по ходу работы. Задача — пройти все фазы до конца и сдать результат.

- **Не останавливайся за подтверждением.** Если нужно принять решение, выбери разумный вариант и запиши его в `docs/DECISIONS.md`: что выбрал, почему, какие были альтернативы.
- **Останавливайся только на жёстком блокере**, который не обходится, например нет доступа к GitHub. Тогда опиши его в `docs/BLOCKERS.md` и доделай всё остальное, что от него не зависит.
- **Коммить часто**, небольшими осмысленными шагами, в ветку `voxa/main-work`. В конце открой PR в `main`.
- **Ты на Linux, а приложение для macOS.** Собрать и запустить `.app` локально нельзя. Сборку и проверку под macOS делай через GitHub Actions на `macos-latest` (§7). UI проверяй в браузере через Vite + Playwright и скриншоты (§4.4).
- **Отчёт в конце** — `docs/FINAL_REPORT.md` (§9).

## 1. Цель

Своё приложение для голосовой диктовки на базе Handy (MIT):
- нажал хоткей → говоришь → текст вставляется в активное поле (Claude, Obsidian, любое приложение);
- **индикатор записи в стиле Liquid Glass**, как в iOS/macOS 26;
- **статистика внутри приложения** (§5);
- полностью локально, без телеметрии и облачных API.

Целевая машина: MacBook Air **M2, 8 GB RAM**, Apple Silicon. Основной язык — русский с английскими техническими терминами.

## 2. Фаза 0 — разведка репозитория

1. Изучи структуру форка: где Rust-ядро (`src-tauri/`), где React UI, как устроены:

   - история (SQLite? схема, миграции);
   - настройки (`settings_store.json` и его типы);
   - пайплайн транскрипции: где вызывается модель, где применяются custom words, где вставляется текст;
   - автообновление и проверка версий;
   - существующие GitHub Actions workflows.
2. Проверь, есть ли доступ к GitHub API из сессии (`gh` или токен): нужно запускать workflow и читать его логи и артефакты.
3. Итог запиши в `docs/ARCHITECTURE_NOTES.md`: карта модулей и точки, которые будешь менять.

**Принцип:** менять upstream-код минимально и точечно, новое класть в отдельные модули (`src-tauri/src/voxa/`, `src/voxa/`). Тогда потом можно будет подтягивать обновления Handy через `git merge upstream/main`. Добавь `upstream` remote на `https://github.com/cjpais/Handy`.

## 3. Ребрендинг и изоляция от Handy

- `productName` → `Voxa`, `identifier` → `com.daniyar.voxa`. Отдельный identifier важен, чтобы не конфликтовать с установленным Handy: свои настройки, история и разрешения macOS.
- Папка данных: `~/Library/Application Support/com.daniyar.voxa/`.
- **Отключи автообновление на upstream Handy.** Иначе обновление заменит форк оригиналом. Либо выключи апдейтер целиком, либо направь его на релизы своего репозитория. Выбор зафиксируй в DECISIONS.md.
- Иконка: простая своя (капля или волна в стеклянном стиле). SVG → iconset через `tauri icon`.
- Сохрани `LICENSE` (MIT) и добавь в README атрибуцию: «Based on Handy by CJ Pais».
- Отключи любую телеметрию и аналитику, если она есть.
- Опционально: при первом запуске предложить импорт custom words из настроек Handy, если файл существует. Только чтение.

## 4. Индикатор записи в стиле Liquid Glass

### 4.1 Дизайн
- **Форма:** «пилюля» (capsule) ~220×48 pt, по центру снизу экрана, отступ ~24 pt от Dock. Положение настраивается: низ / верх / выключено.
- **Материал:**
  - полупрозрачная заливка с размытием фона: `backdrop-filter: blur(24px) saturate(180%)`, фон `rgba(255,255,255,0.14)` в тёмной теме и `rgba(255,255,255,0.45)` в светлой;
  - тонкая светлая обводка с градиентом сверху вниз (блик): 1px, `rgba(255,255,255,0.55) → rgba(255,255,255,0.08)`;
  - внутренний блик сверху: radial-gradient, мягкий specular highlight;
  - мягкая тень: `0 8px 32px rgba(0,0,0,0.25)`;
  - лёгкое преломление на краях: дополнительный слой с `mix-blend-mode: overlay` и маской по краю.
- **Состояния:**
  - **Запись:** живая волна из 5–7 скруглённых столбиков, высота по уровню микрофона (RMS со сглаживанием), плюс таймер `0:07`. Акцентный цвет мягкий, без кислотности.
  - **Распознавание:** столбики «перетекают» в мерцающую шиммер-полоску.
  - **Готово:** галочка, через ~600 мс пилюля растворяется (scale 0.96 + opacity).
  - **Ошибка:** лёгкий красноватый оттенок стекла и короткий текст; через 2 с пилюля исчезает.
  - **Отмена:** ✕ появляется при наведении. Esc тоже отменяет (как в Handy).
- **Анимации:** пружинные (spring), появление — scale 0.9 → 1 + blur → 0, ~280 мс.
- **Доступность:** уважать `prefers-reduced-motion` (без пружин и шиммера) и `prefers-reduced-transparency` (плотный непрозрачный фон вместо стекла). Контраст текста ≥ 4.5:1.
- Оверлей **никогда не забирает фокус** у активного приложения (как в Handy).

### 4.2 Реализация
- Окно оверлея: прозрачное, без рамки, поверх всех окон, игнорирует клики, кроме кнопки ✕.
- **Нативный слой:** за webview включи нативную macOS-вибрацию (`window-vibrancy`, материал HUD), тогда размытие реального фона под окном честное. Стеклянные блики, обводка и анимации — в CSS поверх.
- **Stretch-цель, не блокирующая.** На macOS 26+ попробовать нативный `NSGlassEffectView` через `objc2`. Если за ~2 итерации CI не получается стабильной сборки, откатиться на вибрацию + CSS и записать причину в DECISIONS.md.
- Уровень микрофона передавать из Rust в UI событием ~30 раз в секунду (throttle). Если в Handy такое событие уже есть, переиспользовать его.

### 4.3 Главное окно
Стиль тот же: стеклянные карточки, системный шрифт (SF Pro через `-apple-system`), скругления 14–20 pt, адаптация к светлой и тёмной теме. Существующие экраны Handy (модели, настройки, история) перекрасить в эту систему **через общие CSS-токены**, без переписывания логики.

### 4.4 Визуальная проверка без Mac
- Сделай dev-страницу `/voxa-preview`, где оверлей рендерится во всех состояниях на фоне скриншотов «рабочего стола» (тёмный и светлый). Положи 2–3 фоновых изображения в `docs/assets/`.
- Playwright-скрипт снимает скриншоты каждого состояния → `docs/screenshots/overlay-*.png`. Смотри их сам и итерируй, пока не будет выглядеть аккуратно: читаемо, без грязных краёв, блики не пересвечены.
- В FINAL_REPORT вставь итоговые скриншоты.

## 5. Статистика внутри приложения

Это главное преимущество своего приложения: данные **измеряются прямо в коде**, без прокси и догадок.

### 5.1 Что записывать для каждой диктовки
Расширь таблицу истории миграцией, старые данные не ломать:

| Поле | Источник |
|---|---|
| `duration_ms` | длительность записанного аудио |
| `transcribe_ms` | время от конца записи до готового текста: таймер вокруг вызова модели + постобработки |
| `model_id` | какая модель реально распознавала |
| `language` | выставленный язык |
| `raw_text` | текст модели **до** custom words |
| `final_text` | текст после custom words (то, что вставлено) |
| `replacements_json` | какие замены custom words сработали: `[{from, to}]` |
| `word_count`, `latin_word_count`, `cyrillic_word_count` | считаются при сохранении |

### 5.2 Метрики (экран «Статистика»)
**Базовое:**
- слов надиктовано: сегодня / за неделю (пн–вс) / всё время;
- число диктовок и средняя длина (слов и секунд);
- минуты наговорено (сумма `duration_ms`).

**Качество и модель:**
- задержка `transcribe_ms`: среднее и **p95** по каждой модели. При n < 20 показывать «мало данных»;
- доля латиницы: `latin / words`. Латинское слово — содержит хотя бы одну `[A-Za-z]` (`RAG-пайплайн` считается латинским). Чисто числовые токены не относятся ни к латинице, ни к кириллице;
- **кандидаты в словарь:**
  1. реальные срабатывания замен из `replacements_json`, топ по частоте: какие слова модель ошибается чаще всего;
  2. кириллические транслиты известных терминов из встроенного списка (питон→Python, клод→Claude, докер→Docker, гитхаб→GitHub, обсидиан→Obsidian, лэнгчейн→LangChain, гигачат→GigaChat, фастапи→FastAPI, раг→RAG, эмбеддинги→embeddings, пандас→pandas, стримлит→Streamlit), с учётом падежных окончаний (совпадение по основе);
  3. кнопка «Добавить в словарь» рядом с кандидатом **сразу добавляет его в custom words** приложения.
- таблица сравнения моделей: `модель | n | слов | avg/p95 задержки | доля латиницы`.

**Визуализация:** карточки сверху, столбики «слова по дням» за 30 дней, таблица моделей, список кандидатов. Библиотека графиков лёгкая (Recharts или аналог), в том же стеклянном стиле.

### 5.3 Ограничения
- Время: хранить UTC, показывать в локальной таймзоне системы; граница дня — локальная полночь.
- Лимит истории Handy по количеству **не должен удалять статистику**. Либо храни агрегаты отдельно от текста, либо поставь по умолчанию большой лимит и чисти только **аудио** (через 7 дней), а не текст. Решение зафиксируй.
- Всё считается локально. Никаких внешних запросов.

### 5.4 Тесты
Rust/TS unit-тесты: токенизация (`GPT-4o`, `ёлка`, `e-mail`, `3.11`, `Claude'а`, смешанные алфавиты), p95, транслит-кандидаты с падежами, миграция БД на фикстуре старой схемы.

## 6. Настройки по умолчанию под владельца

- Модель по умолчанию: **Whisper large-v3-turbo**. Добавь в список моделей вариант **q8_0** (`ggml-large-v3-turbo-q8_0.bin`, ~874 MB, источник — `huggingface.co/ggerganov/whisper.cpp`) и сделай его рекомендованным для машин с ≤ 8 GB RAM. Полный turbo (~1.6 GB) и GigaAM v3 оставь доступными.
- Язык: **Russian**.
- Custom words предзаполнены: Claude, Obsidian, LangChain, RAG, GigaChat, FastAPI, Docker, GitHub, Python, pandas, Streamlit, embeddings, PostgreSQL, Sber.
- Если Whisper в коде поддерживает `initial_prompt`, передавай туда естественную фразу с этими терминами («Настроил RAG-пайплайн на LangChain, промпт для Claude, заметка в Obsidian, деплой в Docker»). Поле промпта сделай редактируемым в настройках.
- Хоткей: push-to-talk + отдельный toggle (как в Handy).
- Буфер обмена: восстанавливать после вставки.
- Выгрузка модели из памяти после 10 мин простоя: если опция есть, включить по умолчанию (8 GB RAM).

## 7. Сборка под macOS через CI

- Workflow `.github/workflows/voxa-macos.yml` на `macos-latest` (Apple Silicon), запуск на push в `voxa/**` и вручную:
  1. установка тулчейна (Rust, Bun/Node — как в upstream workflow);
  2. lint + unit-тесты (Rust + TS);
  3. `tauri build` → `.app` для `aarch64-apple-darwin`;
  4. ad-hoc подпись (`codesign --sign -`);
  5. упаковка `Voxa.app` в zip → artifact `Voxa-macos-arm64`.
- После каждого значимого изменения: push → дождаться workflow → прочитать результат и логи упавших шагов → чинить. **Готово, только когда CI зелёный.**
- Если доступа к Actions из сессии нет (Фаза 0), убедись, что код компилируется хотя бы в доступном объёме, и опиши в `docs/BUILD_LOCAL.md` команды локальной сборки на Mac (одна команда), а в BLOCKERS.md — почему CI не проверен.
- **Не трать минуты бесконечно:** максимум ~15 прогонов CI. Если упираешься, зафиксируй состояние и причину.

## 8. Ограничения и подводные камни

- **Ad-hoc подпись:** после каждой пересборки macOS может сбрасывать разрешения «Универсальный доступ» и «Мониторинг ввода» (меняется CDHash). Опиши в README, как перевыдать: `tccutil reset Accessibility com.daniyar.voxa` и повторно выдать в настройках.
- **Gatekeeper:** скачанное приложение получит карантин. В README: `xattr -cr /Applications/Voxa.app`.
- **8 GB RAM:** не добавлять ничего тяжёлого в фон. Никаких локальных LLM в этом плане.
- **Upstream-совместимость:** не форматировать массово чужие файлы и не переименовывать upstream-модули без необходимости.
- **Приватность:** ни одного сетевого запроса, кроме скачивания моделей по явному действию пользователя.

5. Кнопка «Добавить в словарь» работает.

**`docs/FINAL_REPORT.md`:**
- что сделано, по фазам;
